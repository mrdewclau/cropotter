# CropOtter agent access without new recurring costs

The user approved WebMCP, local MCP and an executable skill on 2026-10-22. Deliver all three using the existing shared engine; keep production on the existing DigitalOcean service. Do not provision cloud resources, remote conversion workers, storage, subscriptions, accounts or model APIs.

## Browser route

Feature-detect `document.modelContext.registerTool` on the top-level page. Register tools with abort-scoped cleanup; preserve the ordinary UI when unsupported. Use existing App state and conversion functions, not a second hidden converter. Tools inspect current state, load the synthetic sample, configure the output name/DPI, open crop review, retrieve download metadata and initiate PDF/PNG/ZIP downloads. Loading customer files remains the ordinary file picker/browser upload route. Never return raw PDF bytes, barcode values or external signed URLs as tool text. Blob download URLs are page-local, expire on replacement/reset, and are not public HTTPS artifacts.

All output access must follow the existing review gate. Agents cannot acknowledge human crop review through a tool. Busy, stale/no-document and unacknowledged-review states return actionable errors. Preserve explicit page decisions, cancellation and current crop selections. Filename sanitation matches the UI. Tools must not alter page geometry or introduce controls outside the approved shell.

## Local route

Build a distributable standalone `cropotter-local` npm tarball and downloadable skill ZIP on existing hosting/GitHub. Node 24+, native canvas and local engine assets execute on the caller's machine or agent sandbox. Package contains the compiled engine and CLI/MCP entrypoints, so it does not rely on unpublished workspace packages or TypeScript source tooling. Install dependencies via public npm; no owner account/key/service is needed at runtime.

CLI accepts local input, output directory, formats PDF/PNG/ZIP, filename, 203/300 DPI, analysis mode and explicit crop/page decisions. Preserve review semantics: without deliberate review acknowledgement, uncertain output is withheld, analysis is available, and exit code 2 indicates review required. Name each output safely, avoid overwriting existing files or following output symlinks, include version/geometry/warnings/checksums in a manifest. Bound input and generated output, sanitize errors and avoid logging document content. Caller chooses local paths; no remote URL fetch or HTTP listener is needed for local MCP.

MCP runs over stdio using the official SDK with supported protocol compatibility. Expose local analysis and conversion tools plus access to output resources. Bind readable resources to artifacts generated by that server instance; do not expose arbitrary file-reading tools. No global machine scanning, arbitrary command execution or remotely reachable listener. Local filesystem access is explicitly documented; host attachment presentation is not guaranteed.

## Skill and distribution

Ship an Agent Skills folder with clear runtime requirements, deterministic CLI usage, review/cancellation behaviour and output-file attachment instructions. Bundle the same installable local package into the ZIP, avoiding a skill that merely asks the model to recreate the conversion. Publish a permanent agent guide, package, skill ZIP and machine-readable metadata as static assets on the existing website, with instructions for Codex, Claude Code/Desktop and Gemini CLI. Clearly distinguish verified local operation from untested hosted-sandbox support. Do not promise automatic discovery or universal downloadable attachment UI.

## Acceptance

Test real synthetic PDF conversions through the packed CLI, the stdio MCP client and a skill-style invocation after clean installation outside the checkout. Verify PDF portrait 288x432 points, PNG dimensions, ZIP entries, filenames, warnings/review gate, invalid/oversized inputs, path safety and resource scope. Browser tests invoke actual registered callbacks, then verify UI agreement, stale/reset behaviour, review gating and actual downloaded PDF/PNG/ZIP bytes. Verify WebMCP registration lifecycle and no-support fallback. Native-browser discovery is a separate gate from simulated registration; report unavailable native support honestly.

Run engine/web/local tests, relevant typechecks, production builds and existing viewport/browser regressions. Independently review the diff, resolve findings, publish source/distribution without new paid services, deploy only the CropOtter container, and verify live health, static packages, UI geometry and synthetic conversion/downloads. Update handoff/deployment/verification notes with actual evidence and remaining client-specific limits.
